# PagePilot 0.4.6 验证记录

日期：2026-10-27。环境：Windows、Word 16 x64、200% DPI、.NET Framework 4.8、Office 2010 PIA。以下为本次实际执行结果，不把编译兼容视作 Word 2010 实机验收。

## 公开文档与导航

- 从公开机构网站下载 50 份 DOCX，50 个不同 SHA-256：13 份中文、33 份英文、4 份威尔士语。包括大学论文指南与模板、政府表单和指导材料、年度报告。18 份 MAPPA 报告共享模板，因此不是 50 种独立版式。
- 来源、文件哈希和选定正反例保存在 `tests/corpus/manifest.json`；原文档不进入安装包或源码包。`tests/fetch_navigation_corpus.py` 可重新下载。
- 全部 50 份在真实 Word 中只读打开，实际读取 18,442 段，解析结果逐项核对原生 Range 的正文和索引。83 项人工选定标题/排除断言，加上 50 项文件完整性检查，共 133 项通过。没有给全部段落人工标注，所以不报告整体准确率。
- 包含打开 Word 文档、读取元数据、分析和原生范围检查的耗时，中位数 3,461 ms，最大 43,193 ms。长文档、跨进程 COM 调用和 Word 分页影响显著；此数字不是单纯算法耗时。
- 独立 OOXML 批测：16,726 个 XML 段落、1,255 个候选标题、8,326 项结构及样例检查，约 1.1 秒。XML 段落数与 Word 的实际段落数不同，生产读取器会对齐文本而非盲用数组下标。
- 55 项导航回归通过，涵盖中英文/中文数字/罗马数字、公式、标题内公式、封面、日期、图表题注、表格误用大纲及标题开关。50,000 段合成压力样例约 812 ms。
- 用户提供的黎曼猜想文档使用副本验证：导航只保留 8 个章节，排除总标题、副标题和独立公式。原始用户文档未改写。

## 真实 DeepSeek 与连续对话

- 使用用户授权的本地密钥和已安装配置，调用生产 `NavigationAi`，模型 `deepseek-flash`；密钥不进入测试输出、仓库和安装包。
- 公开中文指南：40 个标题、2 批、约 2,858 ms；公开表单：5 个标题、1 批、约 945 ms；英文年度报告：12 个标题、2 批、约 2,090 ms。均通过范围、排除样例和分批检查；不以模型输出数量代表完整准确率。
- 实测发现目录分类在思考模式下可能用尽输出预算。官方 DeepSeek 请求显式关闭思考；截断时有界拆分重试，其他提供商不附加 DeepSeek 专有参数。
- 连续三轮真实 API 测试通过：首轮包含工具错误，第二、第三轮继续正常；已保存历史、请求序列化和已发布 SDK 的 schema 回归通过。延续 0.4.5 对工具错误消息结构的修复。
- 真实 Word 集成测试验证 AI 进度立即出现、结果正确、取消可用，且文档 XML 保持不变。

## 查找高亮与界面

- 17 项核心回归通过，包括正则超时、Unicode、结构保护及 100,001 项匹配（约 131 ms）。真实 Word 的输入防抖、域后的匹配范围、单击定位、批量替换与单步撤销通过。
- 高亮采用有色底纹与原画面相乘的方式，黑色像素保持黑色，灰色抗锯齿像素不会被变亮。像素测试验证自选颜色、背景确实有填充、重叠匹配不累积染色，以及窗口消息钩子释放。
- 实际界面测试发现并修复两个边界：大页边距导致页首匹配漏标；Word 平滑滚动时逻辑位置先于画面，可能捕获旧文字。现在从可见锚点双向定位，滚动时立即隐藏旧标记，合并 100 ms 内的变化，分帧测量后再等绘制机会，并核对连续两帧像素指纹，采集稳定画面。快速连续滚动时标记会短暂隐藏，停止后恢复；不会修改文档底纹或字体。
- 最后一次真实 Word 自动回归：滚动使可见起点从 0 变为 27，5 个测量片段，总测试动作约 734 ms；单个片段最长 84 ms。8 ms 是片段之间的软预算，不能中断一次耗时较长的 Word 调用，不能据此承诺固定帧率。100% 到 125% 缩放自动更新矩形尺寸通过。
- 使用 computer-use 实际操作 Word：打开用户文档副本、打开导航、点击章节定位、打开查找并输入“零点”（43 项）；在实际 Word 测试文档上滚轮滚动，确认旧标记消失、稳定后正确恢复，黑字与有色背景同时保留。另外修复首次显示采用系统默认窗口位置、覆盖实测视口位置的问题，并限定高亮操作使用物理像素 DPI 上下文。已安装插件中的滚轮及拖动滚动条复测通过。界面操作阶段发现的问题均修正后复测；并非仅依据截图设计稿判断。
- 设置页在 620/880 像素宽度检查通过：九级字体设置、深色预设、自选高亮色、保存回读、控件不横向溢出。导航实际选中态为浅薄荷底与深色文字，展开按钮采用较大的线条箭头。懒加载、取消与选中态也有 WPF 集成检查。
- 144 项部署回归通过。Release 构建通过；NuGet 漏洞服务连接失败产生 NU1900，使用缓存依赖构建，不把这一结果视作漏洞审计通过。

## 设计参考与使用

参考 [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)、[Material Design in XAML](https://github.com/MaterialDesignInXAML/MaterialDesignInXamlToolkit) 和 [WPF UI](https://wpfui.lepo.co/documentation/) 的对比度、间距、焦点与控件层级原则。实现使用限定范围的 WPF 资源字典，不引入额外启动依赖。事件失效机制参考 [NativeWindow](https://learn.microsoft.com/dotnet/api/system.windows.forms.nativewindow)；AI 参数依据 [DeepSeek 思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。

设置 → 阅读与导航：选择主题、查找高亮颜色、九级字体样式、选中态、行间留白、缩进、最大行数及识别偏好。改变识别偏好后重新分析，不自动修改文档大纲；“应用大纲”是独立操作。

## 本地安装验证

最终候选安装在 `D:\APP\PagePilot-0.4.6\PagePilot`。新建 Word 进程自动加载成功，实际连接报告 0.4.6；启动及连接验证约 2,290 ms。只读打开用户的指数时间猜想文档，导航面板调用返回约 586 ms，实际进程内分析 77 段、9 个标题约 1,306 ms，正文与保存状态保持不变。

## 范围限制

标题识别仍为启发式规则、样式与 AI 的组合，不宣称覆盖所有版式。扫描版本冲突会要求重新分析。巨大文档、受保护内容、混合 DPI、多个显示器、远程桌面和 Word 2010 完整实机矩阵尚未穷尽验证。AI 时间取决于网络与服务状态；本次公开样本的指标不可外推为所有机器的性能保证。
