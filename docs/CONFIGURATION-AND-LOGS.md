# 自定义存储与事件日志（0.4.1）

在部署器左侧选择 **存储与日志**。可以分别指定运行配置文件、规则与文档备份目录、AI 模型与会话目录、日志目录。保存前关闭 Word；下次打开 Word、AI 助手和设置时使用新位置。

## 配置文件

完整示例见根目录 `runtime.example.json`。默认配置文件为 `%LOCALAPPDATA%\PagePilot\runtime.json`；没有默认文件时使用内置默认值。自定义配置文件的位置保存在当前用户 `HKCU\Software\PagePilot\Runtime\ConfigFile`，不会要求其他账户使用同一配置。

| 字段 | 用途 | 默认值 |
|---|---|---|
| SchemaVersion | 配置格式版本 | `1` |
| DataDirectory | 偏好、标题规则和文档备份 | `%LOCALAPPDATA%\PagePilot` |
| ProfileDirectory | Chatbox 配置、会话与设置缓存的父目录 | `%APPDATA%\PagePilot` |
| LogDirectory | 部署器、Word、Electron、MCP 事件日志 | `%LOCALAPPDATA%\PagePilot\logs` |
| LogLevel | `debug` 为详细，`info` 减少高频事件 | `debug` |

路径支持 `%LOCALAPPDATA%` 等环境变量；相对路径以配置文件所在文件夹为基准。配置限制为 64 KB，未知版本、未解析的环境变量和不可写目录会报错。点击“读取所选配置”只预览，点击“保存并使用配置”才启用。配置损坏时 Word 回落到默认路径并记录错误，部署器会提示修复后再部署。

“复制旧配置与会话”默认勾选：保留旧文件，不覆盖目标已有文件，跳过缓存和部署事务。应选择独立的新目录，避免新旧目录相互包含。现有日志留在原日志目录，不自动迁移。部署回退记录固定保存在 `%LOCALAPPDATA%\PagePilot\deployment`，因此更换日志位置不会丢失回退入口。

## 一键打开和导出

部署器侧边栏与“诊断详情”页都有 **打开日志文件夹**。文件夹不存在时会先创建。点击 **完整诊断** 查看环境和注册状态，点击 **导出诊断包** 生成新的 ZIP 文件。

诊断包包含环境报告、运行日志和最近一次部署事务。它不会收集模型配置、聊天数据库、文档副本、正文、API Key 或会话令牌；环境报告仍包含 Windows 账户、SID 和本机路径，分享前可检查。日志是应用主动埋点的操作事件，不是系统级事件审计，也不记录每次键盘输入或模型消息。

## 记录范围

| 文件 | 主要事件 |
|---|---|
| `manager.jsonl` | 启动与账户权限、页面和操作、文件校验、Word 关闭/强制结束、注册写入与回读、部署恢复/回退、配置迁移、验证结果、诊断导出 |
| `host.jsonl` | Word 连接/启动/断开、加载项版本、功能区与窗格加载、设置保存、进程启动、正则查找/替换、导航读取、文档备份、工具批准、桥接请求结果与耗时 |
| `electron-<PID>.jsonl` | 助手/设置进程启动、窗口显示/隐藏/关闭、无响应、渲染失败、Word 请求结果与耗时 |
| `bridge-<PID>.jsonl` | MCP 启动、工具调用名称、完成/错误状态、耗时及异常类型/堆栈，不记录工具参数和返回正文 |
| `state/word-<PID>.json` | Word 进程启动时间、版本路径、连接与功能区加载回执，供部署器验证使用 |

每行 JSON 包含 UTC 时间、进程号、组件、级别、事件名称和详情。部署操作还带有操作编号。`debug` 包含高频状态查询和查找事件；`info` 保留主要操作与错误。各日志文件约 4 MiB 轮转，保留 3 个备份。Electron/MCP 按进程生成文件，**总日志目录没有固定容量上限**；长期使用可在关闭 PagePilot 后归档旧日志。

日志写入失败不会中断文档操作；Word 和部署器尝试写入默认日志目录。Electron/MCP 日志写入失败时会跳过该事件，因此无法保证磁盘不可写、进程被强制终止或系统崩溃时最后一条事件落盘。

## 排查首次没有加载项

1. 用平时运行 Word 的同一个 Windows 账户打开部署器。通常无需管理员权限；以其他管理员账户运行可能写入不同用户的注册项。
2. 选择“启用此版本”。若 Word 仍在运行，先请求正常关闭并处理保存提示；无响应时可确认强制关闭，未保存修改会丢失。
3. 选择“启动 Word 并验证”。“已注册”仅表示注册回读正确；“已验证”要求当前版本连接 Word 且功能区已加载。
4. 超时后 Word 保持打开。检查首次启动/激活提示、文件 → 选项 → 加载项 → COM 加载项，以及“禁用项目”。部署器只读检查 Office 禁用记录，不自动清空。
5. 再次执行诊断并导出 ZIP，同时说明失败时间、是否切换账户、是否管理员启动、后续尝试是否成功。

用户提供的旧日志证明曾成功连接 Word 14.0 并打开相关界面，但不能证明第一次失败的原因，也不能证明必须管理员启动。此次增加事件链和实际回执，供后续复现判断。
